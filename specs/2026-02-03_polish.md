## 1. Documentation

**Current state**: No README or user documentation exists.

### README.md Structure

- [ ] **Overview** - What Echoport does, target audience (homelab)
- [ ] **Quick Start** - Clone, install deps, configure `.env`, migrate, run
- [ ] **Architecture** - Brief diagram showing Echoport ↔ FastDeploy ↔ MinIO flow (link to PRD for details)

- [ ] **Safe Usage** (critical for SQLite backups)
  - Echoport uses `sqlite3 .backup` which is safe for live databases, but prefer low-traffic windows for large DBs
  - Restore stops the service before overwriting files
  - Backups include SHA256 checksum; restore verifies checksum before applying
  - How to verify a backup: `tar -tzf <backup>.tar.gz` to list contents
  - Warning: `.env` files are NOT backed up (secrets managed by ops-control)

- [ ] **Secrets & Environment**
  - Required env vars: `DJANGO_SECRET_KEY`, `FASTDEPLOY_BASE_URL`, `FASTDEPLOY_SERVICE_TOKEN`
  - Optional: `ECHOPORT_CACHE_DIR` (lock file location)
  - MinIO credentials configured via `mc alias` on the server (not in Echoport's .env)
  - Recommended `.env` permissions: `chmod 600`

- [ ] **Management Commands**
  - `backup <target>` - Run manual backup
  - `run_scheduled_backups` - Check and run due scheduled backups (called by cron)
  - `cleanup_old_backups` - Delete backups older than retention_days
  - `create_devdata` - Create development targets
  - `ensure_superuser` - Create/update admin user (used during deployment)

- [ ] **Troubleshooting**
  - Backup stuck in PENDING: Check FastDeploy logs, verify service token
  - MinIO upload failed: Check `mc alias` configuration, bucket permissions
  - Restore blocked: Restore requires a valid checksum; re-run backup if checksum is missing
  - Scheduled backups not running: Check cron/service logs (e.g., `/home/echoport/logs/scheduler.log`)
  - Permission denied: Verify backup script is root-owned, check sudoers config

- [ ] **Limitations**
  - SQLite only (no PostgreSQL support yet)
  - Single-host (macmini) - no multi-host support
  - No client-side encryption (relies on MinIO server security)
  - No multi-user access control (single admin user)

- [ ] **Deployment** - Link to ops-library role, brief mention of `just deploy`

### Scope Notes
- Keep concise - homelab project, not enterprise docs
- Link to PRD for architecture decisions
- No PDF/printable version needed

## 2. Modal Dialog Fix

**Current state**: The `.confirm-dialog` (`<dialog>` element) appears squeezed in the upper left corner.

**Root cause**: Browser default positioning varies for `<dialog>`.

**Fix**:
```css
.confirm-dialog {
    position: fixed;
    inset: 0;
    margin: auto;
    max-width: 450px;  /* tune if dialogs vary in width */
    max-height: 90vh;
    overflow-y: auto;
}
```

**Testing**:
- [ ] Centered on desktop viewport
- [ ] Centered on narrow mobile viewport (375px width)
- [ ] Content scrollable if dialog exceeds viewport height
- [ ] No off-screen content on small screens

## 3. Dark Theme Support

**Current state**: Light theme only with CSS variables in `:root`.

**Approach**:
- Use `prefers-color-scheme` media query (auto-detect, no toggle)
- `:root` variables are the single source of truth - no per-component overrides
- Override all existing `:root` variables (the list below is complete)

**Deliverables**:

```css
@media (prefers-color-scheme: dark) {
    :root {
        --color-bg: #0f172a;
        --color-surface: #1e293b;
        --color-border: #334155;
        --color-text: #f1f5f9;
        --color-text-muted: #94a3b8;
        --color-primary: #60a5fa;
        --color-primary-hover: #3b82f6;
        --color-success: #4ade80;
        --color-warning: #fbbf24;
        --color-error: #f87171;
        --color-info: #22d3ee;
        --shadow-sm: 0 1px 2px rgba(0, 0, 0, 0.3);
        --shadow-md: 0 4px 6px -1px rgba(0, 0, 0, 0.4);
    }

    /* ::backdrop only applies to <dialog> elements */
    .confirm-dialog::backdrop {
        background: rgba(0, 0, 0, 0.7);
    }
}
```

**Testing checklist**:
- [ ] Dashboard cards

- [ ] Links (normal, hover, visited)
- [ ] Focus rings (keyboard navigation)
- [ ] Tables

- [ ] Restore warning box
- [ ] Confirm dialog + backdrop
- [ ] Login page

**Test targets**: One desktop browser (Safari or Chrome) + iOS Safari

## 4. Justfile Documentation Commands

**Current state**: No commands for viewing docs.

**Deliverables**:
- [ ] `just readme` - View README (use `bat` if available, else `cat`)
- [ ] `just spec` - Open current spec file in `$EDITOR` (fallback to vim)
- [ ] `just commands` - Static list of management commands with one-line descriptions

**Implementation**:
```just
# View README
readme:
    @if command -v bat >/dev/null 2>&1; then bat README.md; else cat README.md; fi

# Open current spec in editor
spec:
    ${EDITOR:-vim} specs/2026-02-03_polish.md

# List available management commands
commands:
    @echo "Management Commands:"
    @echo "  backup <target>          - Run manual backup for target"
    @echo "  run_scheduled_backups    - Check and run due scheduled backups"
    @echo "  cleanup_old_backups      - Delete old backups per retention policy"
    @echo "  create_devdata           - Create development backup targets"
    @echo "  ensure_superuser         - Create/update admin user"
```

Keep it simple - static list, no discovery system.
